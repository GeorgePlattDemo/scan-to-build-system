# Admission requirements

**Owner:** System. **Status:** record of what admission checks today. Recorded at `main` 3c93cc1; since then `admit()` checks the fields of fourteen nested facts (`start-own.material`, `start-own.parts`, `start-own.datum`, `start-own.spot-demand`, `alcove.material`, `alcove.board-requirements`, `alcove.component-programs`, `alcove.spot-demand`, `window-seat.boards`, `window-seat.added-knobs`, `window-seat.kept-asks`, `outdoor.cut-packages` (both scopes), `playhouse.sheet`, `playhouse.opening`), each only for the fields its live page already emits. Every other row is unchanged.
**Layers recorded:** the admission profiles in [`apps/stb/shared/tile-host-admission-contract.mjs`](../../apps/stb/shared/tile-host-admission-contract.mjs) (`admit()`, read first by every tile), and the old path, `admitPublicStoreRequest` in [`apps/stb/public-build/stb-public-admission.mjs`](../../apps/stb/public-build/stb-public-admission.mjs), which still runs inside `sendJob` (`stb-store-client.js`) after `admit()` has admitted and `inquire()` has called the tile's transport. No tile's inquiry runs both layers today. Start your own, Playhouse, Window Seat, Alcove and Outdoor have one: each transport sends the admitted request through `sendAdmittedJob`, which does not call `admitPublicStoreRequest`, so the `O:start-own.*`, `O:playhouse.*`, `O:window-seat.*`, `O:alcove.*` and `O:outdoor.*` rows below run only for a direct `sendJob` call (TT), never for a Start your own, Playhouse, Window Seat, Alcove or Outdoor inquiry (Outdoor: neither `OUTDOOR_OPTIONS` nor `OUTDOOR_COMMITTED`). Where such a row's Status says unported (`O:start-own.unresolved`, the exact-payload equality of `O:window-seat.generator-consistency`, the `selectionAuthority` `STORE_ZERO` item check of `O:alcove.board-requirements`, `O:alcove.unresolved`, the `material` object and nonempty parts of `O:outdoor.required-values`, the exact-payload equality and options identity pattern of `O:outdoor.generator-consistency`), that check no longer runs on that tile's inquiry. `O:alcove.hardware` no longer runs on an Alcove inquiry either: hardware travels as a Store-owned open demand (`alcove.hardware`), as before. The Store pin is still checked by the transport (`loadConfig`).
**Check:** [`apps/stb/test/trail/admission-requirements-table.test.mjs`](../../apps/stb/test/trail/admission-requirements-table.test.mjs) reads the fixture [`apps/stb/test/fixtures/admission-requirements.mjs`](../../apps/stb/test/fixtures/admission-requirements.mjs). It fails if a profile requirement, an old-path row or an old-path failure code exists that this table does not list, or if a row here has no owner or no destination.
Terms (job-definition revision, Store inquiry, admissible) are defined once in [definitions](../definitions/README.md). The interfaces are in [TILE-HOST-ADMISSION-CONTRACT.md](TILE-HOST-ADMISSION-CONTRACT.md).

How to read the table:

- **Check** names the layer. `P:` is a profile requirement (`id@scope`). `O:` is an old-path responsibility row. `G:` is an old-path gate or failure code that applies to every tile. `K:` is one kept ask on Window Seat.
- **Owner** is who must settle the fact. Where the old row named a different owner, the cell says so.
- **Valid form** is what the check accepts today, not what it should accept. **A nonempty object is not a complete fact.** Where a profile accepts any nonempty object (or any nonempty list) and completeness comes from elsewhere, the cell says so and names where. Where the profile names the fields (its `form`), a settled fact missing one blocks in `admit()` with `INVALID_VALUE`, the fact id, its owner and the missing field paths (`fields`).
- **Source** is where the value comes from on the page.
- **Blocking condition** is what stops the inquiry before the Store today.
- **Test** names the test that exercises the check, or `none`. Short names: **C** `test/trail/tile-host-admission-contract.test.mjs` (*case 4*: a malformed nested fact blocks, a complete one reaches the Store); **U** `test/unit/start-own-admitted-transport.test.mjs` (real bridge and Store client, network recorded); **H** the tile's `test/integration/<tile>-shared-host.test.mjs` ("a missing profile fact blocks…": *omission* means the fact is left out and must block; *admitted set* means only its presence in an admitted request is asserted); **PL** `test/integration/playhouse-live-store.test.mjs`; **TT** `test/integration/trail-terms.test.mjs` (old path, called directly through `sendJob`).
- **Destination** is where the check lives once the old path retires. *Ported*: the profile or `admit()` already carries it. *Transport*: the tile's transport inside `inquire()` carries it. *Constant*: the value is written by the transport, not taken from a fact, so the old check cannot fail on the live page. *Unported*: the check exists only in the old path; nothing in the new path carries it yet. Unported checks are not dropped: each names the place it would go. None is added here.
- **Kept asks** have one disposition each: *included* (sent to the Store), *excluded* (kept on the job, not sent), or *blocking* (stops the inquiry). The profile fact carries only a count. A count is not a disposition; the dispositions below come from the page.
