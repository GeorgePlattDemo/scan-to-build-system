# Current Build Doctrine

The accepted application and its planning lineage establish several durable build rules for post-app work:

- The build model receives architecture; it is not asked to rediscover Scan-to-Build.
- Ask Store for an answer, not its database.
- The job carries part truth. The machine carries cell truth.
- Imported evidence is not automatically fabrication truth.
- A rendered/buildable-looking object is not proof that the commissioned machine can make it.
- Product variety should come from bounded upstream definition plus reusable machine functions, not claims of universal machine capability.
- Physical execution is a separate controls/safety/commissioning horizon.
- Application → Governed Core → Store → machine-neutral job → commissioned cell lowering → local program → local controller → drives/tooling/sensors/actuators.
- The application does not generate live motion, remotely invoke Cycle Start, assert `POSITION_VALID`, allocate stock, or invent Store capability.
- Old prototype behavior may be preserved only where its semantics survive current owners.
- New worked identity is User 1; Sarah remains historical provenance/donor material.
