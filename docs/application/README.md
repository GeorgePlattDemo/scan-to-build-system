## Application semantic rule

Application work must preserve the shared meanings owned by Program and the executable contracts owned by System.

Protected distinctions include:

- `DefinitionReviewRecorded` is review, not commerce or authorization;
- `UnresolvedDefinitionAcknowledged` is acknowledgment, not resolution;
- Store `SUPPORTABLE` is not governed acceptance or physical approval;
- Q / `BudgetaryEstimate` is not automatically a commercial quote;
- modeled cycle time is not measured production time;
- applicable/current is not automatically live/fresh;
- Store evaluation, commercial assent, local readiness, controller acceptance, and physical execution remain separate.

## Build posture

Future application work extends the current System application rather than reconstructing a donor prototype.

User 1, new project classes, intake adapters, Store interactions, and later machine/cell visibility should be added through the owning current boundaries.

Historical Grok plans and prototypes remain useful lineage where explicitly cited. They do not silently become current instructions.

**Do not compress engineering truth to simplify the application. Compress the interface to that truth.**
