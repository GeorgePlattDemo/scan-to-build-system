## Current application truth

The accepted app is not an empty shell. It includes entry/routing, project identity, evidence custody, observation mapping/correction, bounded Board definition and revision, Stage-2 Store integration, definition review, truthful result, owner-record export/import/reopen, and integrated first-vertical acceptance.

It remains local/reference software. It does not contain production authority, physical execution, ordering, payment, reservation, fulfillment, or cloud custody.

## Post-app language rule

The recent application language cleanup is the default vocabulary for application work.

Historical Sarah/demo language does not override it.

Protected distinctions include:

- `DefinitionReviewRecorded` is review, not commerce or authorization;
- `UnresolvedDefinitionAcknowledged` is acknowledgment, not resolution;
- Store `SUPPORTABLE` is not governed acceptance or physical approval;
- Q / `BudgetaryEstimate` is not a commercial quote;
- modeled cycle time is not measured production time;
- applicable/current is not automatically live/fresh;
- Store evaluation, governed authority, local readiness and Cycle Start remain separate.

## Build posture

Future app work should extend the accepted architecture rather than return to prototype-specific flows.

User 1, Store 1, new project classes, additional intake adapters and later machine/cell visibility should be hung on the accepted architecture through the owning boundaries.

**Do not compress engineering truth to simplify the application. Compress the interface to that truth.**
